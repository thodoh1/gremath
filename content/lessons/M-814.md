## 3. Precise statement

A recursive algorithm calls itself on smaller inputs; an iterative one uses a loop. The same recurrence can be implemented either way. Recursion depth costs stack space; tail recursion can be converted to a loop. Correctness of recursion is induction on input size.

Copy that statement onto paper and replace each symbol with a tiny example. A definition you cannot instantiate is a definition you do not have.

## 5. Worked example

**Problem.** Factorial: recursive $n\cdot(n-1)!$ vs a loop multiplying $1..n$. Same $T(n)$?

**Solution.** Both $\Theta(n)$ arithmetic steps (ignoring bit-cost of large integers).

Now cover the solution and redo it. If you cannot, you are still in Section 2.

## 6. GRE-style problem

**Problem.** Naive recursive Fibonacci $F_n=F_{n-1}+F_{n-2}$ time is $\Theta(\phi^n)$. Iterative?

**Solution.** $\Theta(n)$ by storing the last two values.

Notice what was *not* done: no extra theory, no calculator, no essay. The governing idea, then the computation.

## 7. Traps that cost points

- Assuming recursive always slower, or that iteration cannot implement DFS (it can, with an explicit stack).
- Skip checking a candidate in the original equation.

## 8. Drills

Work these closed-book. Then check.

**Drill 1.** Binary search recursive vs iterative. $T(n)$?

**Solution.** Both $\Theta(\log n)$ comparisons on a sorted array.

Cover that solution, redo the drill on paper, then continue.

**Drill 2.** Why does naive recursive Fibonacci recompute $F_3$ many times when computing $F_{10}$?

**Solution.** The recursion tree branches and overlaps; no memoization.
